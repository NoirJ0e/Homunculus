# 2. 共治：玩家/NPC 纯叙事，AIDM 是唯一状态写入者

- 状态：Accepted
- 日期：2026-06-01

## 背景

需要定"行动如何表示"。结构化意图（`grab(idol)`）能让确定性引擎自动检测碰撞、结算、追踪状态，但要维护一层 indirection，工程代价与摩擦都高，且不像文字团。纯叙事最自然，但把所有机械裁决压给解读者。

底层原则（共治）：创作型 Agent 只负责判断/叙事/扮演，确定性引擎持有并维护唯一权威状态。

## 决策

- **所有人（真人 + NPC）只写散文**。不维护"每个行动挂结构化意图"的 indirection 层。
- **AIDM 是唯一的"叙事 → 状态"翻译官，也是唯一能写权威状态的角色**：仅当它判断"机械要紧了"（掷骰、改 HP、裁碰撞、改在场名单、改场景、commit/merge 分支）时，由它发出结构化工具调用更新引擎。
- **碰撞由 AIDM 像真人 DM 一样读记录时注意到并裁定**（两人扑同一神像 → 喊对抗检定），不是确定性检测。
- **骰子是纯叙事的一个显式口子**：检定不由 AIDM 静默翻译，而是 AIDM **喊话**（"Kovach 过一个困难侦查检定"），由**要掷的那个角色亲手发出 SealDice 命令**——真人自己打 `.ra 侦查`，NPC Agent 吐出 `.ra 侦查` 这条结构化命令。这是 NPC "只写散文"的唯一例外。

## 备选

- **纯结构化**：像电子游戏，真人摩擦大，丢散文味。否决。
- **混合（散文 + 抽取的结构化意图）**：表达力与确定性兼得，但维护 indirection 负担高。否决，让位于纯叙事的简单。

## 后果

- **AIDM 成为所有机械裁决的瓶颈**——这是本项目标记的最大风险。双重缓解：按系统判定卸给 SealDice（[ADR-0001]）；"扮演整个队伍"结构性拆给 NPC Agents。赌注：AIDM 忙得过来。
- 确定性引擎对游戏机制"半瞎"，只经 AIDM 之手被喂——可接受，因为唯一真相源因此清晰。
- 元游戏防护：玩家/NPC 只看到公开记录 + 自己的私有上下文，无法作弊。
