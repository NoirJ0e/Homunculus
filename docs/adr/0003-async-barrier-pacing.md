# 3. 异步屏障节奏模型：无限期 hold = 暂停

- 状态：Accepted
- 日期：2026-06-01

## 背景

多 AI 群聊的真实痛点：AI 零延迟抢跑，真人一 AFK 就被冲走、毫无参与感（实测的 COC 惨案）。需要一个既不冷场、又不碾压玩家的节奏机制；同时不希望任何创作型 Agent 背上"调度一群演员"的负担。

## 决策

- **拓扑**：自治内容 + 一个**瘦节奏层**。调度权从所有创作型 Agent 剥离；节奏层不是创作 Agent。
- **屏障 + 无限期 hold**：AIDM 抛出需回应的节点后，这一拍 hold 住，直到被等者都"行动 or 明确 pass"。**真人 AFK → 无限期 hold**（不超时、不 AI 兜底）。
  - 副产品：**无限期 hold 天然就是"暂停 / 今晚到此为止"状态**；存档 = 序列化当前拍 + 还在等谁。系统因此是**异步、事件驱动，无墙钟**。
- **屏障触发**：AIDM 写完散文后**额外吐一个控制信号** `awaiting:[在场者]` 或 `continue`。引擎据此 hold 或放行。因此"节奏闸/Director" **坍缩进确定性引擎**，不是独立创作 Agent。
- **拍内多人**：**允许平行发帖**（贴文字团真实感——两人同扑神像是常态，由 DM 裁定，非 bug）；前置一个**廉价两段唤醒闸**（小模型判"有话说吗"，只有"说"的才跑完整生成），既保自治又压注意力。反应靠**跨帖涌现**（人人读更新的记录），不靠拍内强制串行。
- **沉默语义**：AI 返回 pass = 明确空过；**真人单纯沉默 ≠ pass**（走无限 hold），只有显式"pass/你们继续"才算。**全员明确 pass → 唤醒 AIDM 推进**；**只要有真人既不行动也不显式 pass → 继续 hold**。唯一的"冷场"恰是"真人全沉默不 pass"= 暂停状态。

## 备选

- **水流式推进**：谁说谁接，持续向前——正是 COC 碾压 bug 的根因。否决。
- **AIDM 当总指挥**：把调度负担压回 AIDM。否决（违背第一性原理）。
- **超时后 AI 兜底 / 跳过玩家**：否决，选无限 hold（顺带得到暂停语义）。
- **拍内强制串行**：更"对话式"，但 over-engineering 且不如平行真实。否决。

## 后果

- **注意力主胜利靠"每 NPC 一个 Agent"结构性锁定**；唤醒闸只是真实感 + 边际成本的次要优化，其灵敏度是 playtest 旋钮。
- v1 场景小（约 4 人 + 几 NPC），每 NPC 每广播一次廉价判定完全扛得住；pillar 3 规模上去再叠启发式预筛（向后兼容）。
