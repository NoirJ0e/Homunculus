# 8. 情节记忆召回 v1：最近性 + 关键词（接口可替换）

- 状态：Accepted
- 日期：2026-06-01

## 背景

[ADR-0004] 把灵魂记忆定为两层：**常驻人格核心**（永远在上下文，防失忆/OOC）+ **情节记忆**（可召回的自传体事件流，按场景作用域、分支感知）。它在"后果"里留了一个寄存项：需要一个**记忆召回**子系统，"v1 可先简单（关键词/最近），后续增强"。本 ADR 把这句话敲成 v1 的具体实现路线，并把替换点固定下来。#7 落地。

## 决策

- **v1 召回策略 = 最近性 + 关键词重合**，**不引入向量库 / embedding**。
  - 每条情节记忆带：`sceneId`（写入即作用域）、单调递增的 `seq`（最近性）、`summary`、`tags`（关键词）。
  - `recall(soul, {tags?, scenes?, limit?})`：先按 tag 重合度排序，`seq` 倒序（更近的优先）做 tiebreak，`slice(limit)`。
- **作用域 = 写入即正确**：一个灵魂的情节列表里只会有它**亲历过的场景**的记忆（写入时带 `sceneId`），因此"不会召回未亲历场景"是构造性保证，不依赖读取时再过滤；`recall` 的 `scenes` 参数是可选的更细控制（[ADR-0005] 视界）。
- **巩固节奏（consolidation）v1**：暂不做离线压缩/向量化；情节流直接追加，引擎按最近性取前 N 条注入上下文。反思 pass（#9）在场景收尾写入结构化记忆/人格更新——那是写侧，与本召回读侧解耦。
- **替换点 = `recall` 的签名**：未来 embedding 版召回保持相同的 query/return 形状（`RecallQuery` → `EpisodicMemory[]`），引擎与上层无需改动即可换实现。`MemoryWrite`/`EpisodicMemory` 的 schema 保持稳定可演进。

## 备选

- **v1 直接上向量库 / embedding**：召回质量更好，但引入索引、嵌入模型、巩固节奏一整套复杂度，在核心多智能体价值尚未验证前是过早投入。否决（推迟，接口已留好）。
- **全量塞上下文（不召回）**：会爆 context、会失焦（[ADR-0004] 已否决单层记忆）。否决。
- **读取时按当前 horizon 过滤记忆**：与"灵魂只持有亲历记忆"重复，且会错误地屏蔽灵魂自己过去场景的记忆。否决，改为写入即作用域。

## 后果

- 召回是**纯确定性函数**，可脱离 LLM 单测（符合本仓库测试范式）。
- 升级到向量召回是**局部替换**（只换 `recall` 实现），不波及引擎、上下文装配、上层切片。
- v1 的关键词召回质量取决于 tag 质量；tag 由写侧（反思 pass / AIDM）产出，是 playtest 旋钮。
- 召回灵敏度（`limit`、tag 提取粒度、是否引入巩固）随真实跑团再调。
