# 5. 场景=可见性单位；兵分两路=严格隔离的 git 分支

- 状态：Accepted
- 日期：2026-06-01

## 背景

TTRPG 信息天然不对称：DM 密语单人、单人偷骰、PC 间秘密、DM 独有的模组底牌。把一切广播给所有人会制造元游戏作弊。同时队伍会兵分两路甚至多路，不同组看到不同的事。需要一个既防作弊、又能表达"分头行动"的信息/并发模型。

## 决策

### 信息模型
- **共享聊天记录 = 唯一的公开真相**。唯一的不对称是"各 Agent 的私有上下文（DM 模组底牌、角色私密背景）"与"它选择发到群里的话"之差。**DM 藏东西的方式就是根本不发**。所有人只针对群里实际出现的有限信息行动。

### 可见性 = 场景成员资格
- **场景是一等公民状态对象**（含在场名单）。**一个场景的记录只对其成员可见。**
- **私频 = 成员很少的场景**；DM 密语某人 = 临时的二人场景。DM 全知在场；玩家 Agent 只看得见自己所属场景。
- 副产品：一个 Agent 的**记忆视界 = 它参与过的场景集合**，元游戏防护自动涌现。
- 场景成员由 AIDM 经工具调用（共治）增删，确定性引擎维护。

### 兵分两路 = git 分支
- 分裂 = fork 出多条分支，各有独立 DM 实例**并发推进**，最后 merge 回主线。
- **严格隔离契约**：只允许沿"互不相交的状态接缝"分裂——两组触碰不相交的世界状态、分裂期间不互相产生因果影响。**于是 merge 是确定性的 delta 并集，永不需要 retcon。** 危险情形（两组同时影响同一东西）直接禁止，或强制先合流再行动。
- **角色记忆不跨分支 merge**（各组只记得自己那条，重逢后靠剧情转述）——元游戏防护再次免费。只有全局世界状态需要 merge。
- 节奏漂移（无真人的全 AI 分支会跑过头）被隔离化解：两线互不影响，merge 时按"剧情发生过"并入，不要求墙钟对齐。

## 备选

- **全广播给所有在场者**：制造元游戏作弊。否决。
- **彻底单一公开频道（无私频）**：放不下密语/偷骰/兵分两路。否决。
- **受众标记 + 强制路由**：可行但比"DM 不发就是藏"复杂。否决。
- **兵分两路用 DM 切镜（时间切片，非真并行）**：更省，但用户选了真并行 git 分支。否决。
- **自由发散 + merge 时 LLM 叙事仲裁**：要 retcon、圆场，玩家可能已基于旧事实演过。否决，选严格隔离。

## 后果

- merge 是确定性并集，不需要 LLM 仲裁。
- 真并行带来"多 DM 实例 + 共享状态"复杂度，靠严格隔离驯服。
- 私频/兵分两路复用同一个 scene 对象，不引入"可见性矩阵"新原语。
