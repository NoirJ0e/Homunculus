骰子 / 规则引擎选型

Homunculus PRD#2 · A（机械域）路线调研 · 2026-06-02

评分用例（不是"哪个骰子 bot 最好"，而是"哪个最适合我们")

  • 无头驱动：由我们的 TS 引擎/AIDM 程序化调用，不依赖真人在聊天框里敲指令。
  • 不冒出第二个 bot：频道里只应出现我们的 agent 分身；骰子引擎必须在幕后，不能是另一个会发言的聊天机器人（ADR-0001 红线）。
  • 多系统：至少 CoC7 + D&D5e，按系统判定成功/失败/大成功。
  • 能实现 DicePort：现有引擎只对着这个端口（NativeDice 已实现它），所以选型 = 换一个适配器实现 + 编排，引擎不动、锁定度低。
  • 角色卡归属：叙事灵魂（soul）一定归我们；机械卡（sheet）归谁可谈——但"谁拥有卡"决定集成复杂度（ADR-0001 的双头冲突）。

逐个详评

① BCDice 推荐

日本最流行的 TRPG 骰子判定引擎，覆盖数百个系统。关键在于它有两种干净的无头形态：

  • 官方 TS/JS 移植 npm i bcdice（bcdice/bcdice-js，在维护）：进程内 DynamicLoader 动态加载系统（如 Cthulhu7th），求值 CC<=54 返回结构化结果对象（.text + 成功/大成功/大失败）。无服务器、无聊天、无第二 bot——直接在我们 TS 里实现一个 DicePort。
  • bcdice-api：官方 Web API 服务器形态（也有公共实例 + Go 移植 GoBCDice），适合不想进程内嵌时用。

取舍：它是纯判定器，不管角色卡——所以"卡归我们（soul + sheet 存自己的库）、判定交 BCDice"。这正好不是 ADR-0001 担心的那种双头冲突（那是针对 SealDice 想拥有卡）：BCDice 不抢卡，分工天然干净。待核实：BCDice 的强项是 CoC + 日系，D&D5e 的判定深度需要实测确认（属性调整、熟练加值、优势/劣势是否覆盖到位）。

→ 与我们架构契合度最高：进程内库实现 DicePort，多系统 + 结构化，零第二-bot，引擎不动。

② rpg-dice-roller（npm）

成熟、流行、MIT 的 骰子表达式引擎（优势/劣势、爆炸、保留/丢弃、数学式）。但它只算骰子，不懂系统规则、不管卡——"CoC 困难侦查算不算过"这种系统判定要我们自己写。本质上≈我们 NativeDice 现在做的事，只是表达式更全。

→ 想要更强的骰子表达式时可替换 NativeDice 内部用它；但它不提供"按系统判定"，撑不起 A 的"真机械结算"。

③ NativeDice（现状）

仓库里已有、已实现 DicePort、种子 rng、COC7/DND5e 判定，且 call_check/roll/.ra 链路都在——只差接 live + 真结构化卡。零新依赖、最快，足以验"一整场可玩"。

→ PRD#2 的"现在就能动"选项；之后在同一端口后面平滑换 BCDice。

④ SealDice 海豹（当前/基线）

成熟、CN 社区活跃、自带多系统 + 卡管理。但对外驱动只走 OneBot v11 反向-WS（SealDice 去连一个本该是 QQ 登录框架的反向-WS 端点）；它自带的 HTTP 是管理 Web UI，不是骰子/卡 RPC。所以集成 = 我们自写一个 OneBot v11 服务端桥 + 发合成消息事件（.st/.ra）+ 解析它的自然语言文字回复（脆）。且它本质是会发言的聊天 bot，有"第二个 bot"风险。

→ 最重的集成、最脆的接口；除非看重它的 CN 生态/规则库，否则不划算。

⑤ Avrae（D&D Beyond 官方）

开源（Python，avrae/avrae，可 Docker 自托管），D&D5e 专精：从 D&D Beyond/Dicecloud/Google Sheet 读卡、自动算攻击/检定/豁免、战斗追踪、Draconic 脚本。但它就是一个 Discord 机器人 + 只支持 D&D5e——绑死 Discord（第二 bot）、单系统，与我们"多系统、agent-only、无头"的需求正面冲突。

→ 若我们是"纯 D&D5e + 纯 Discord"会很香；但我们不是。不推荐作无头引擎。

结论与建议

选型 = 一个 DicePort 适配器决定，锁定度低（引擎只认端口）。按契合度：

  1. 目标态：BCDice（npm bcdice 进程内库） 实现 DicePort，卡仍归我们（soul+sheet 自存）。拿到成熟、多系统、结构化判定，且不引入聊天 bot / OneBot 桥。前置实测：D&D5e 判定深度是否够（打个 spike：加载 DnD5e 系统，跑几条攻击/检定/优势，看结构化输出）。
  2. 过渡/现在：继续 NativeDice 把 A 接 live（call_check→投→结算→叙事 闭环 + 真结构化卡）。零新依赖、最快验"一整场"，之后在同一端口后面换 BCDice。
  3. 放弃 SealDice / Avrae 作无头引擎：前者非干净 RPC（OneBot 桥 + 脆解析 + 第二 bot），后者单系统 + 绑 Discord。

推荐路径：PRD#2 先用 NativeDice 把机械闭环接 live（不阻塞"一整场"北极星）；并行打一个 BCDice spike 验 D&D5e 深度，通过则把 DicePort 实现换成 BCDice。两者共用端口，互不返工。
